# 网盘轻量版评估：目录浏览 + 批量上传/下载 + 资源管理器右键上传

> 2026-10-14 · 范围收缩版分析（相对《网盘个人空间同步-技术业务分析.md》：**不做自动同步**，只做手动批量传输）
> 接口证据全部来自同日 AIF/DCP 双会话 curl 实测，见前一份文档 §1.2

---

## 1. 业务必要性评估

### 1.1 分功能判断

| 功能 | 必要性 | 判断依据 |
|---|---|---|
| 目录浏览 | **低** | 与 B/S 网页个人空间完全同构，客户端做一遍只是换壳；且现有「空间」tab 已能跳 webview 打开 knowledge 页面 |
| 批量下载 | **中** | B/S 网页端**没有**"整个目录打包下载"（deleteList/draftList 之外未见批量下载端点），只能逐篇点下载；客户端按目录勾选批量拉取是真实增量 |
| 批量上传 | **中高** | 网页上传窗口一次最多 20 个、需在 webview 里层层点选；客户端原生文件对话框 + 队列化（可>20 分批）有体验增量 |
| **右键菜单上传** | **高** | 这是本方案的价值锚点：在资源管理器选中文件 → 右键直达个人空间，把"上传"从 5 步网页操作变成 2 步本机操作；也是唯一让客户端网盘功能区别于"又一个网页"的点 |

### 1.2 结论

- **纯"浏览+上传/下载"的客户端页面，单独存在意义不大**（B/S 网页已是完整实现），必须靠右键菜单把它变成系统级能力才成立。
- 使用频率决定价值：AIF 运维报告归档、DCP 基层资料回传都是**周期性批量动作**，右键直达的收益随每次操作稳定兑现。
- 不做自动同步反而降低了风险敞口（无删除语义、无冲突、无后台常驻带宽），业务解释成本低："这是一个往个人空间传/取文件的工具"。
- **建议**：做，但以右键上传为 MVP 核心，浏览/下载作为配套页面存在。

## 2. 技术评估

### 2.1 目录浏览与批量下载 —— 无硬阻碍，两个待补测点

已实测可复用：`findTree.htm`（目录树）、`findTreeByNodeId.htm`（扁平节点含 FILE 文章）、`downloadfile.htm`（单文件下载，实测 9MB 200）。

**待补测 1（P0）**：批量下载需要每篇文章的 `filepath`/`fileSize`，目前只在 `detail.htm` 页面注入的 JSON 里拿到过；`knowledge/article/findById.htm`（个人空间页源码可见）大概率是 JSON 版元数据接口，**需实测确认**——若可用则下载清单一次拿全，否则要逐篇请求 detail.htm（N 次请求，需做并发限流）。
**待补测 2**：无服务端打包下载端点 → 只能客户端逐文件拉取，进度 UI 与失败重试按文件粒度做。

### 2.2 批量上传 —— 已知约束三条

1. `fileSave.htm` 单次 ≤20 个文件（knowledge.js 源码明示 `fileNum: 20`）→ 客户端按 20/批分批落库，上传本体 `uploadfile.htm` 逐文件 POST 不受此限。
2. 单文件 100MB（上传窗口配置 `size: 100`），无断点续传 → 超限文件前置拦截提示，失败整文件重试。
3. 顺序约束：必须**先传文件拿 annexId，再 fileSave 落库**，两阶段之间崩溃会留下孤儿文件（B/S 网页同样如此，非新增风险，但客户端要自己做"队列持久化 + 重启续传"避免半截状态）。

### 2.3 资源管理器右键菜单 —— 本方案最大的技术问题集中在这里

三条实现路线对比：

| 路线 | 做法 | 优点 | 缺点/风险 |
|---|---|---|---|
| A. 静态注册表 verb | HKCU 写 `Software\Classes\*\shell\AifUpload\command = 客户端exe --upload "%1"`（多选用 `"%*"` + `MultiSelectModel`） | 半天工作量；纯 HKCU 免管理员；NSIS 打包即装即卸；Rust 侧只是解析 argv | **Windows 11 默认折叠进"显示更多选项"二级菜单**（现代顶层菜单只认 COM 扩展）；菜单项不能带动态状态 |
| B. 发送到（SendTo） | 往 `%APPDATA%\Microsoft\Windows\SendTo` 放快捷方式 | 几乎零成本；天然支持多选 | 入口更深（右键→显示更多选项→发送到）；文案不直观 |
| C. IExplorerCommand COM 扩展 | Rust windows-rs 实现 COM DLL，`HKCU\...\shellex\ContextMenuHandlers` 注册 | **Win11 现代菜单顶层显示**，可带图标/标题，体验对标 7-Zip 新版 | 工作量 3~5d；DLL 架构必须匹配（ARM64/X64 各一份，本项目双架构打包正好覆盖）；**签名问题**：未签名 DLL 在部分环境被策略拦（巨鹏客户政企环境常见）；需要自注册/卸载清理；调试成本高 |

**建议分两步**：MVP 用路线 A（`"%*"` 支持多选文件，托盘客户端单实例接收——tauri `single-instance` 插件转发 argv 到已运行实例，弹目标目录选择浮层后进上传队列）；路线 C 作为体验升级项，先在巨鹏内部机器验证签名策略再决定是否上。

其余技术点：

- **目标目录选择**：右键多文件后需选"传到哪个目录"——复用客户端 UI 弹一个目录树选择浮层（数据源 findTree），记忆上次选择；产品维度跟随当前登录产品（AIF/DCP 会话隔离，spaceId 相同但数据不同，必须按 `ops_product` 分流——这是已实测确认的行为）。
- **会话依赖**：右键触发时若未登录/会话过期 → 客户端唤起登录页，登录后自动续传（对齐现有 auth 机制，无新问题）。
- **安全**：argv 传路径需处理带空格/中文路径引号转义（Windows 惯例 `"%1"`）；HKCU 注册不需要管理员权限，卸载时 NSIS 同步删键。
- **与现有约定无冲突**：不新增常驻线程、不动 ACL（右键走进程 argv 不走 invoke），不影响打包流程（NSIS 段加注册表写入即可）。

### 2.4 工作量

| 项 | 预估 |
|---|---|
| 目录浏览 UI（复用 spaces tab 模式）+ findById 补测 | 1~1.5d |
| 批量下载（队列/进度/重试） | 1.5~2d |
| 批量上传（20/批分批 + 队列持久化） | 1.5~2d |
| 右键菜单路线 A + 单实例转发 + 目标选择浮层 | 1~1.5d |
| 路线 C（可选升级） | 3~5d |
